# Risk Analysis

| Risk | Likelihood | Impact | Mitigation actually taken |
|---|---|---|---|
| Depending on an external, unmodifiable `A-Maze-ing` package whose interface the team doesn't control | Medium | High (blocks level generation entirely if incompatible) | Isolated all dependency behind a single wrapper class (`MazeGen`), so any interface mismatch is fixed in one file. Errors from the generator are caught rather than allowed to crash the game. |
| Two people editing the same files causing merge conflicts | Medium | Medium | Work was split along the logic/GUI boundary (see `03-project-analysis.md`), which kept people out of each other's files almost all the time — only one conflict is recorded across 123 commits (`3338de6`, Aug 21). |
| A 9-day period with zero commits (Aug 26–Sep 4) eating into the schedule | High (it happened) | High — compressed remaining feature work, sound, polish, linting, docstrings, and packaging into roughly one week | The team ran a dense sprint from Sep 5 onward (57 of 123 commits landed in the final week, most in the final 3 days). It worked, but left linting/type-checking as a last-day activity done twice (see `07-blocking-points.md`), which is the riskiest way to do it. |
| `flake8`/`mypy --strict`-style checks failing right before submission | Medium | High (subject treats lint as mandatory, non-negotiable) | Lint and mypy were run and fixed on Sep 12 (`fixed: Flake&mypy`), then broke again after adding docstrings and had to be fixed a second time (`Refix Flake8 after adding Docstrings`) on the same day. Mitigated in the moment, but confirms lint should be run continuously, not once at the end. |
| Assets/paths breaking once the game is packaged with PyInstaller (works from source, fails when frozen) | Medium | High (packaging is a mandatory deliverable) | Caught during packaging work on Sep 12 and fixed with `get_asset_path()` applied at every load site before submission — but this was found late, on submission day, leaving little margin if it hadn't been simple to fix. |
| Public-platform deployment (Steam/itch.io) not confirmed until after the main submission window | Materialized, briefly | Medium | Closed out on Sep 13 (`open_game_page.sh`), one day after the rest of the project — published unlisted at https://iazzhim.itch.io/pac-man. Worth noting for next time: platform deployment was the last mandatory box ticked, not something planned for alongside packaging on Sep 12. |
| Highscore file corruption or absence on first run | Low | Low (subject explicitly asks for this to be handled) | `highscores_caching()`/`top_scores()` were written to tolerate a missing/invalid file, per the README's own description of the highscore system. |
| Informal workflow (direct commits to `main`, commit messages occasionally in Darija/shorthand rather than structured tickets) making it harder to reconstruct decisions later | Low | Low for a 2-person team, but this exact document had to be built from raw `git log` rather than an issue tracker | For future projects, using GitHub Issues/Projects (which the team reportedly set up) consistently, with linked commits, would make this kind of retrospective analysis unnecessary. |
